# Revdo audit 001

Date: 2026-09-27

Scope: public site, responsive navigation, admin dashboard, Node server, content data, image assets and project checks. This is a review of the current repository state. No application files were changed.

## Findings

### 1. HIGH: Static file denylist can be bypassed with encoded path traversal

`server.js:176-206` checks the decoded pathname against a list of private paths, then resolves and serves that path. An encoded slash keeps `..` segments intact while `new URL()` parses the request; the later `decodeURIComponent()` restores the traversal segments. The prefix-only containment check also accepts paths whose names merely begin with the project root. I reproduced this locally: a request for `/assets/%2e%2e%2f%2e%2e%2fRevdo/server.js` returned HTTP 200 and the server source, while `/server.js` returned 404.

This defeats the source-file denylist and could expose other files reachable by the server process. Resolve paths against the root with a separator-aware containment check, reject traversal after canonicalization, and preferably allowlist public paths instead of maintaining a denylist. Add regression checks for encoded separators and dot segments.

Reference: `AGENTS.md` Project Rules, source and internal-file protection; antislop C-4 (resilience).

### 2. MEDIUM: Mobile drawer does not manage keyboard focus

`index.html:16,32-37,60-62` moves the drawer off screen and sets `aria-hidden="true"`, but its links remain in the keyboard tab order while closed. Opening the drawer does not move focus into it or contain focus; closing it does not restore focus. The menu button also keeps the accessible name “Open menu” while the menu is open. On narrow screens the icon has no visible “Menu” label.

Make the closed panel inert or otherwise remove its links from focus navigation. On open, move focus into the drawer and keep it there until close; restore focus to the menu button afterward. Keep its accessible name in sync with open state and make the menu discoverable visually.

Reference: antislop R-03, R-26, R-32; antislop-human Keyboard and Focus & States; antislop-layoutmobile Mobile Navigation.

### 3. MEDIUM: Several small text pairings fail WCAG AA contrast

The contrast checker reports `#8f897d` on `#ede8df` at 2.85:1, used by muted text and labels on the light page. It reports `#7d776d` on `#0e0e0c` at 4.35:1, used by small footer headings. Both fail the 4.5:1 requirement for normal text. These values appear in `index.html:11,19,22`.

Adjust the muted text colors and verify every text/background pairing, including translucent text over the hero image, with the bundled contrast checker.

Reference: antislop R-25; antislop-human Color & Contrast.

### 4. MEDIUM: CMS accepts navigation slugs with no matching page

The admin editor allows adding or changing navigation entries (`admin.html:46-48,63,67`). The server only checks that `nav` is an array (`server.js:160-173`), while the public site has five fixed views (`index.html:39-44,60`). If an editor adds a slug such as `about`, the router accepts it because it is in the menu, then hides all five views because `view-about` does not exist. The content area becomes blank.

Validate navigation slugs against implemented views, reject duplicates, and make the editor communicate which pages it can route to.

Reference: `AGENTS.md` Project Rules, real menu routes; antislop C-2 and C-4.

### 5. MEDIUM: Login throttling trusts an unverified forwarding header

`server.js:94-122` keys the login failure limit from the first `X-Forwarded-For` value whenever that header is present. A client can choose that value unless a trusted reverse proxy removes incoming copies and sets its own. This can let repeated login attempts use a fresh key each time. The in-memory map also has no cap or cleanup for arbitrary keys.

Use the socket address unless the app is behind a configured trusted proxy, then accept forwarded addresses only from that proxy. Expire and cap rate-limit entries or enforce the limit at the proxy.

Reference: `AGENTS.md` Project Rules, conservative admin security; antislop C-4.

### 6. LOW: Two footer links are placeholders

`data/site.json:169-174` sets Instagram and Are.na to `#`. Clicking either returns the visitor to the top of the current page instead of opening a profile. Replace these values with confirmed profile URLs or remove the links.

Reference: `AGENTS.md` Project Rules, real links; antislop C-2.

### 7. LOW: Admin data-load failures do not produce a visible error state

`admin.html:51-54,74` catches a failed session check, but if a valid session exists and `load()` fails, `init()` rejects without showing an error in the dashboard. The editor stays empty and the failure is only visible in the browser console. The public site has a load-error message; the admin should also explain the failure and offer a retry.

Reference: antislop R-27; antislop-human Focus & States, Missing UI States.

### 8. MEDIUM: CMS allows unsafe footer destinations and remote image URLs

The CMS accepts arbitrary footer `href` values and image URLs. A `javascript:` footer destination can create an executable link when the public site renders CMS content. Remote image URLs can also cause visitor browsers to contact unreviewed third-party hosts.

Allow only supported internal routes, `mailto:`, `tel:` and HTTPS links without embedded credentials. Restrict CMS image paths to local assets. Filter unsafe footer entries in the public renderer as defense in depth.

Reference: antislop C-4 (resilience); OWASP Unsafe URL and untrusted destination handling.
